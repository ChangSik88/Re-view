# 루미 자유 대화

- 로그인 후 AI 채팅에서 메시지를 입력하거나 음성 입력 후 전송합니다.
- 기존 `/chatting/session`, `/chatting/message` API와 Gemini 연결을 사용합니다. 같은 화면에서 이어지는 대화는 같은 세션에 저장됩니다.
- 서버 응답을 기다리는 동안 준비 중 표시를 보여 주며, 응답을 받으면 앱에서 세 글자씩 표시합니다. 서버 토큰 스트리밍(SSE)은 아닙니다.
- 백엔드는 이전 대화와 최신 메시지를 각각 한 번 전달하고, 루틴에 맞는 답변과 `analysis.story_details`를 반환합니다.
- 장소·등장인물·감정·상황·메모는 사용자가 언급한 정보로 채웁니다. 해당 화면에서 직접 수정한 필드는 AI가 덮어쓰지 않습니다.
- 비로그인/디자인 미리보기에서는 실제 AI를 호출하지 않습니다. 로그인 안내를 표시합니다.

## 앱의 JSON 기반 꿈 해석

모닝루틴의 `/chatting/message`도 `dreamKeywordHarness.py`와 300개 키워드 카탈로그를 사용합니다. 이전 USER 발화와 최신 메시지에서 Gemini가 등록 키워드를 최대 2개 선택하고, 백엔드가 정확히 일치하는 JSON 해석·조언만 루미의 최종 답변 프롬프트에 넣습니다. 같은 응답에서 `story_details`도 계속 반환하므로 앱의 직접 입력·정보 확인 흐름은 유지됩니다.

나이트루틴은 이 조회를 건너뜁니다. 일치 항목이 없으면 등록 자료 없이 일반 대화를 이어갑니다. 외부 서비스는 Gemini이며 웹 검색이나 외부 해몽 사이트 수집은 하지 않습니다. 자료 조회/AI 호출 실패를 성공한 해석으로 위장하지 않고 기존 앱의 오류 처리로 전달합니다.

이 연결은 백엔드 변경이므로 배포 후 기존 로그인 앱의 채팅에도 적용됩니다. 별도의 꿈 해석 저장 필드나 상세페이지 API를 추가하는 작업은 포함하지 않습니다.

오프라인 검증: 의존성 설치 후 저장소 루트에서 `PYTHONPATH=BE python -m unittest discover -s BE/tests -v`를 실행합니다. 실제 Gemini 호출 대신 모델 대역을 사용하며 카탈로그 조회, 대화 프롬프트 반영, 정보 필드 보존, 미일치 처리, 나이트루틴 분기를 검사합니다.

## 적용 및 확인

백엔드 변경과 Flutter 앱 빌드를 모두 배포해야 정보 자동 채우기까지 적용됩니다. 서버의 기존 Gemini 인증 및 DB 설정이 필요하며 API 키를 앱에 넣지 않습니다. 기존 서버에서도 답변 표시 효과는 사용할 수 있습니다.

`FE`에서 `flutter test`를 실행합니다. `lumi_chat_test.dart`는 서버 대역으로 점진 표시, 세션 재사용, 추출 정보 반영, 사용자 수정 보존, 실패 시 입력 복구를 검증합니다. 실제 Gemini 응답 품질과 운영 서버 로그인은 별도로 확인해야 합니다.


## 나이트루틴 대화 마무리와 하루 리포트

상단 `대화 마무리`는 사용자 대화가 있을 때만 저장을 시작합니다. 저장 중에는 중복 실행을 막고, 실패하면 채팅 화면에 머무릅니다. 기존 `/chatting/diary` API로 대화를 정리해 ChatSession 본문에 저장하고, 저장된 기록을 다시 조회한 후 하루 리포트 화면으로 이동합니다. 뒤로가기는 이 저장 동작을 호출하지 않습니다.

나이트 생성 프롬프트는 `오늘 있었던 일`, `주요 감정`, `하루 돌아보기` 세 부분을 요청하며 사용자가 말하지 않은 사실이나 감정을 만들지 않도록 지시합니다. 이 형식 적용에는 백엔드 배포가 필요합니다. 일별 리포트는 기존 기록 본문을 활용하며, 여러 기록을 종합하는 기존 AI 감정 인사이트 리포트와는 별개입니다. 기존 기록도 전체 본문을 표시합니다.

Figma 나이트 채팅(516:1114)의 마무리 버튼은 하루 리포트(552:370)로 연결됩니다. 프로토타입은 저장 완료 예시를 보여주며 실제 API 저장은 앱에서 수행합니다. 기록 정보 보기는 Figma에서는 오버레이, 앱에서는 펼침 영역으로 제공합니다.
