# 약관·동의·계정 복구 API 연결

## 적용

루트에서 가상환경을 활성화한 뒤 기존 배포 절차에 따라 `prisma migrate deploy --schema=BE/prisma/schema.prisma`를 실행하고 `BE/`에서 `prisma generate`를 실행한다. 운영 DB는 배포의 마이그레이션 단계에서 적용한다. 이번 작업에서는 로컬 임시 DB에서만 검증했다.

`20261116000000_terms_consent_recovery` 마이그레이션에 약관 8개의 0.1 초안 본문을 스냅샷으로 포함했다. 본문은 DB에서 제공하므로 Markdown 파일을 수정해도 이미 등록된 버전은 바뀌지 않는다. 공개 문구를 확정하면 새 버전의 약관 행과 본문을 마이그레이션으로 추가한다. 과거 약관 행·본문은 보존한다.

현재 문서는 `is_draft=true`로 전달된다. 마케팅·제3자 제공·결제 문서는 미정 항목이 있어 `is_active=false`로 등록했다. 목록과 동의 가능한 항목에서 제외하지만 ID로 전문을 조회할 수 있다. 나머지 초안도 운영자 등 대괄호 항목을 공개 전에 확정해야 한다.

## 경로

| 메서드·경로 | 인증 | 응답 |
|---|---|---|
| `GET /terms` | 없음 | 현재 활성·시행 버전의 목록 |
| `GET /terms/{term_id}` | 없음 | 특정 버전의 전문·메타데이터 |
| `POST /users/signup` | 없음 | 기존 회원가입 응답 |
| `GET /users/me/consents` | Bearer JWT | 현재 동의 대상의 내 상태 |
| `PATCH /users/me/consents` | Bearer JWT | 변경 후 내 상태 |
| `POST /users/restore` | 본문의 아이디·비밀번호 | 복구 성공 메시지 |

## 약관 표시

목록의 `result`는 `term_id`, `term_type`, `version`, `title`, `is_required`, `requires_consent`, `is_active`, `effective_at`, `content_url`, `is_draft`를 가진다. 상세 조회는 같은 정보와 Markdown 문자열 `content`를 반환한다. `content_url`은 JSON 상세 API 경로다.

`requires_consent=true`인 항목만 체크박스로 표시한다. `is_required=true`이면 필수 동의다. 개인정보 처리방침·탈퇴 안내는 전문 열람용으로 제공한다. `term_id`를 고정하지 말고 목록에서 읽는다. 같은 `term_type` 중 시행 시각과 ID가 가장 최신인 활성 버전을 사용한다.

## 회원가입

```json
{
  "id": "example-user",
  "password": "example-password",
  "name": "닉네임",
  "age_over_14_confirmed": true,
  "consents": [
    {"term_id": 1, "is_agreed": true},
    {"term_id": 2, "is_agreed": true},
    {"term_id": 4, "is_agreed": false}
  ]
}
```

ID는 예시다. 필수 약관은 모두 포함해야 하며 선택 약관은 생략하면 미동의로 취급한다. 생년월일·성별은 전송하지 않는다. 기존 Flutter 가입 요청은 변경된 규격에 맞춰야 한다. 만 14세 이상 확인은 현재 자기 확인값과 서버 검증으로 구현됐으며 신분·연령 인증 기능은 포함하지 않는다.

회원 생성과 동의 기록은 한 트랜잭션으로 처리한다. 동의 저장 실패 시 회원도 생성되지 않는다. 응답은 기존처럼 `message`, `result.user_id`, `result.id`, `result.name`이다.

## 동의 조회·변경

```json
{
  "consents": [
    {"term_id": 4, "is_agreed": false}
  ]
}
```

조회·변경 응답의 `result`에는 동의 대상 약관 메타데이터와 `is_agreed`, `decided_at`, `revoked_at`가 포함된다. 변경할 항목만 보낸다. 이력은 덮어쓰지 않고 행을 추가한다. `decided_at`은 수락·거부 결정을 기록한 시각이다. 약관 버전이 바뀌면 과거 버전의 수락을 새 버전의 수락으로 간주하지 않는다.

필수 약관을 `false`로 바꾸는 요청은 거부한다. 필수 처리에 관한 철회·탈퇴는 탈퇴 절차로 처리한다. 기존 회원은 동의 이력이 없으면 미동의로 조회되며, 신규 약관 강제 적용 시점은 프론트·운영 정책에서 확정해야 한다. 기존 회원의 일반 API 접근을 일괄 차단하지 않는다.

연구 동의 철회 시 연구용 사본을 같은 트랜잭션에서 삭제한다. 원래 개인 기록은 이 API로 삭제되지 않는다.

## 탈퇴·복구

기존 `DELETE /users/me`는 성공 시 계속 `204`를 반환한다. 탈퇴 신청 시 토큰 인증 버전을 증가시키고 선택 동의를 철회하며 연구용 사본을 삭제한다.

```json
{
  "userAccount": "example-user",
  "password": "example-password"
}
```

위 본문으로 `POST /users/restore`를 호출한다. 30일 기한 내 탈퇴 계정만 복구하며 일반 로그인 토큰은 요구하지 않는다. 성공 응답은 `{"message":"계정이 복구되었습니다. 다시 로그인해 주세요."}`다. 이후 기존 로그인 API를 다시 호출한다. 복구해도 이전 토큰은 유효해지지 않고, 철회된 연구·마케팅 동의도 자동 복원하지 않는다.

복구와 영구 삭제는 같은 사용자 행을 잠가 처리한다. 기한 경과 후에는 아직 물리 삭제되지 않았더라도 복구를 거부한다.

## 오류

| 상태 | 의미 |
|---|---|
| `400` | 필수 동의 누락·거부, 만 14세 이상 확인 미동의, 중복 아이디 |
| `401` | 만료·무효·탈퇴 계정 토큰, 복구 아이디·비밀번호 불일치 |
| `404` | 약관 ID 없음 |
| `409` | 최신 동의 가능한 약관과 불일치, 비활성 항목 동의, 복구 기한 경과·대상 없음 |
| `422` | 필드 누락·중복 약관 ID·잘못된 형식·생년월일·성별 등 허용하지 않는 가입 필드 |

`409`가 약관 변경에 따른 오류라면 목록을 다시 읽고 새 전문을 보여준 뒤 사용자에게 다시 선택하게 한다. 기존 체크 상태를 자동 수락으로 전송하지 않는다.

## 연구·마케팅 작업의 연결 지점

연구용 테이블은 `research_samples`이며 일반 회원 API로 내용을 공개하지 않는다. 실제 데이터 가명처리·모델 학습 파이프라인은 이번 범위에 포함하지 않았다.

수집 작업은 가명처리한 정보를 `ResearchService.store_sample(user_id, sanitized_payload, source_created_at)`에 전달한다. 현재 버전 연구 동의와 활성 계정을 확인하고, 원본 수집·생성일로부터 5년 만료일을 기록한다. 미래·만료된 원본 날짜는 거부한다. `ResearchRepository.eligible()`는 현재 동의와 기한을 만족하는 후보만 반환한다. 별도 파일로 내보내는 학습 파이프라인을 추가하면 투입 직전 동의를 다시 확인하고 철회 시 파일 사본·진행 작업에도 처리를 연결해야 한다.

광고 발송 작업은 발송 직전 `ConsentRepository.permits(db, user_id, term_type)`를 확인한다. 현재 마케팅 약관은 비활성이므로 허용되지 않는다. 채널별 약관·수신 동의와 실제 발송업체를 확정한 뒤 연결한다.

## 삭제·분리 보존

서버 시작 후와 실행 중 매시간 만료 계정·연구 데이터·분리 보존 기록을 확인한다. 서버가 슬립·중단된 동안에는 실행되지 않으며 다음 시작 시 재개한다. 외부 이미지 삭제 실패 시 해당 계정의 DB를 유지해 재시도한다.

실거래가 확인된 구매·결제·배송 기록은 `retained_records`에 5년 보존하고, 문의는 3년 보존하도록 구현했다. 문의 유형 구분이 현재 없어 전체 고객문의에 3년을 적용한 구현 기준은 운영 정책 검토가 필요하다. 비밀번호·꿈·연구 사본은 분리 보존하지 않는다. 보존 기간이 지나면 정리한다. 이 테이블을 조회하는 일반 회원 API는 제공하지 않는다.

## 검증

로컬 PostgreSQL의 임시 스키마에서 실제 라우터·Prisma 트랜잭션을 검증한다. 테스트용 DB에만 `TEST_DATABASE_URL`을 설정하고 `BE/`에서 다음 명령을 실행한다.

```text
python -m unittest discover -s tests -p test_consent_api.py -v
```

검증에는 필수·선택 동의, 회원 생성 롤백, 동의 철회와 연구 사본 삭제, 만료 데이터 정리, 복구 기한·동시 복구, 과거 토큰 차단, 이미지 삭제 실패 재시도와 분리 보존을 포함한다. 외부 AI·실제 Storage 호출과 Flutter 화면은 검증 대상에 포함하지 않는다.
