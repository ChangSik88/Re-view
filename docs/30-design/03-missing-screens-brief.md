# 미작성 화면 디자인 브리프

Figma `WF(앱버전)` 캔버스(`104:433`)에 **아직 없는 화면 5건**의 작업 지시다. 이 화면들이 나와야 해당 기능의 이관이 시작된다.

관련: [Figma 앱 인벤토리](02-figma-app-inventory.md) · [BE 갭 조사](../50-specs/2026-09-19-app-redesign-be-gap.md) · [감정 라벨 ADR](../40-decisions/0002-emotion-label-taxonomy.md)

## 공통 규격

리디자인 화면들의 실제 픽셀에서 뽑은 값이다.

| 항목 | 값 |
|---|---|
| 프레임 크기 | `393 × 852` |
| 배경 | `#FFFFFF` (채팅 화면만 `#F8F8FF`) |
| 포인트 | `#6E63FF` |
| 연보라 서피스 | `#E8E8FF`, `#F5F3FF`, `#E9E9FF` |
| 하단탭 | 홈 / AI-채팅 / 스토어 / 설정 — 4개 |

> **주의**: `docs/30-design/01-design-tokens.md`는 **구버전 다크 테마** 기준이다(`bg #100D10`, `primary #8F6CFF`). 리디자인은 라이트 전환이고 포인트 색도 다르므로 그 문서를 따르지 말 것. 해당 문서는 이관 0단계에서 갱신 예정이다.

**캔버스 배치**: 새 프레임은 기존 밴드 규칙을 따른다. y 좌표로 도메인이 나뉘고(홈 ≈250 / 인증 ≈1421 / 대시보드 ≈2636 / 루틴 채팅 ≈3855 / 스토어 ≈4981), `참고자료들`(`155:1282`, x 7082~13201) 안쪽은 구현 대상이 아니므로 그 밖에 배치한다.

**이름 규칙**: 현재 캔버스는 레이어명이 내용과 어긋나는 사례가 많다(`채팅 홈`이 실제로는 감정 인사이트 탭이었다). 새 프레임은 **화면명 · 상태** 형식으로 명확히 달아줄 것. 웹 캔버스(`1:36`)의 `D · 맑음 · F1 입력` 같은 규칙이 좋은 예다.

## 1. 꿈 상세 · `AI 감정 인사이트` 탭

**우선순위: 높음** (3단계 이관에 필요)

하루 상세에는 이 탭이 있는데(`554:680`) **꿈 상세에는 탭 버튼만 있고 화면이 없다.**

- 참조: `554:680`(하루 버전), `519:1448`(꿈 · AI 요약 탭), `519:1515`(꿈 · 전문 보기 탭)
- 꿈 상세의 탭은 3개다: `AI 요약` / `전문 보기` / `AI 감정 인사이트`. 앞의 둘은 이미 있다.
- 하루 버전에는 "어제 하루 → 오늘 꿈" 감정 전이가 있다. **꿈 버전의 전이 방향을 정해야 한다** — 꿈에서 하루로 갈지, 이전 꿈에서 이번 꿈으로 갈지. 이게 이 화면의 핵심 결정이다.
- 감정 라벨은 9종 고정: 행복 / 기대 / 설렘 / 편안 / 불안 / 분노 / 슬픔 / 피로 / 놀람. `긴장`·`걱정`은 쓰지 말 것 — `불안`에 통합했다.

## 2. 감정 전체보기

**우선순위: 중간**

대시보드의 3종 원형 위젯에서 `전체보기 >`로 진입한다. 홈의 `Dream Calendar`·`Dream Store` 위젯과 같은 패턴이다.

- 참조: `409:738`(3종 원형 위젯), `515:743`(전체보기 화면의 기존 사례)
- **왜 필요한가**: 링이 3개뿐이라 상위 3개 밖의 감정이 화면에서 사라진다. 디자인의 `31+42+17 = 90`에서 빠진 10%가 그것이다.
- 필수 요소
  - 9종 전체 비율 — **링을 늘리지 말고 가로 막대 목록**을 권한다. 링 3개는 크기를 달리해 배치한 구도라 9개로 확장되지 않는다.
  - 기간 선택 — 최근 4개 / 1주 / 1개월
  - 감정별 기록 진입 — 감정을 탭하면 그 감정이 잡힌 기록 목록으로. 목록 뷰(`519:1347`)를 재사용한다.
- **넣지 말 것**: 감정 변화 라인차트. `AI 감정 인사이트` 탭과 정면으로 겹친다. 둘의 경계는 아래와 같다.

| | AI 감정 인사이트 탭 | 감정 전체보기 |
|---|---|---|
| 진입 | 기록 상세 → 탭 | 대시보드 → 전체보기 |
| 기준 | 특정 기록 1건 | 기간 전체 |
| 범위 | 그 날짜 전후 4일 | 선택한 기간 |
| 감정 수 | 상위 3종 | 9종 전부 |

## 3. 설정

**우선순위: 높음** (하단탭 4개 중 하나라 비워둘 수 없다)

현재 앱은 이 탭을 누르면 "아직 준비 중인 기능입니다! 🚀" 스낵바만 띄운다.

- BE 스키마에 이미 있는 것 — 이 범위 안에서 정하면 구현이 빠르다
  - `UserNotificationSetting` · `NotificationType` — 알림 종류별 on/off
  - `UserAddress` — 배송지 (단 구매 기능은 이번 범위 밖)
  - `UserConsent` · `Term` — 약관 동의 이력
  - `UserWithdrawal` — 회원 탈퇴
  - `UserDevice` — 기기·푸시 토큰
- 프로필 편집(이름·생년월일·성별)은 `User` 테이블에 필드가 있으나 **수정 API가 없다.** 넣으려면 BE 작업이 추가된다.
- 로그아웃은 현재 FE에 구현돼 있다.

## 4. 검색 결과

**우선순위: 낮음**

대시보드 상단 돋보기(`409:738` 등)의 도착지다.

- **벡터 유사도 검색으로 확정됐다.** 즉 "제목에 그 단어가 있는 기록"이 아니라 **"의미가 비슷한 기록"**이 나온다. 결과 화면이 이 성격을 드러내야 한다 — 검색어와 결과가 글자로 일치하지 않는 게 정상이기 때문이다.
- 참조: 목록 뷰(`519:1347`)의 카드 형태를 재사용하면 된다.
- 유사도 점수를 보여줄지, 빈 결과·짧은 질의 처리를 어떻게 할지 정해야 한다.

## 5. 알림 목록

**우선순위: 낮음**

대시보드 상단 벨의 도착지다.

- `NotificationLog`(제목·본문·발송시각·성공여부)와 `NotificationType`(코드·설명)이 이미 있다. 읽음 여부 필드는 **없다** — 넣으려면 스키마 변경이다.
- 알림 종류를 무엇으로 할지가 먼저다(루틴 리마인더, 리포트 완성, 주간 요약 등). 종류가 정해져야 목록 항목의 모양이 나온다.

## 작업 순서 제안

1·3번이 이관을 막고 있으니 먼저다. 2번은 대시보드 이관과 같이 가면 좋고, 4·5번은 기능 정의가 선행돼야 해서 마지막이다.

작업이 끝나면 새 노드 ID를 [Figma 앱 인벤토리](02-figma-app-inventory.md)의 "Figma에 아직 없는 화면" 표에서 본표로 옮긴다.
