## 1. 목적과 범위

기능은 이미 완성돼 있다(기존 스펙·계획 Task 1~8 완료). 이 설계는 **그 위에 Figma WF 디자인을 입히는 작업**을 다룬다. 새 API·새 데이터 모델은 없다.

Figma WF 프레임에는 섹션 2개가 있고, 둘 다 이번 범위에 포함한다.
- `05 · 홈→해몽결과 플로우` — 날씨 5종 × 데스크탑/모바일 × 5단계(F1~F5)
- `06 · 꿈 랭킹 전체보기(한지)` — 데스크탑/모바일 × 4단계(F1 기본 / F2 항목 펼침 / F3 해몽 전 / F4 순위 보기)

### 범위 밖
- **밤 테마** — Figma에 `D·밤`/`M·밤` 프레임이 있지만 날씨 API 기반 테마와 별개 축(시간대)이라 적용하지 않는다. 관련 CSS·JS도 추가하지 않는다.
- **랭킹 페이지 검색바** — Figma엔 있으나 기존 결정(카테고리 13종 수준에서는 장식에 가까움)을 유지해 제외한다.
- 새 BE 엔드포인트, 새 DB 컬럼.

|---|---|---|

## 3. 홈 화면(`index.html`)

### 3.1 F1 입력
- 상단바: 로고 "굿모닝 드림"(Gowun Batang) + 날씨 표기 "맑음 · 9/15"(점 + 텍스트).
  - **도시명·기온은 표시하지 않는다**(Figma에 없음). `weather-city` 요소는 id 계약 때문에 남기되 `hidden`으로 두고 채우지 않는다.
- 하늘 영역: 테마별 일러스트 + 부제("맑은 아침이에요") + 헤드라인 2줄. 문구는 테마별로 JS가 교체한다.
- 입력: 하늘/땅 경계선에 걸친 알약 모양 한 줄 입력. `textarea` → `input type="text"`(id 유지, 최대 500자 유지). Enter로 제출된다.
  - 버튼: 640px 초과 "해몽 받기" 텍스트 / 640px 이하 원형 "→" 아이콘.
- 하단 "오늘 아침 많이 찾는 꿈" 미리보기: **홈에서도 `GET /demo/ranking`을 호출**해 상위 6개를 카드로 표시(640px 이하 3개). 카드와 "전체보기 →"는 `ranking.html`로 이동. 실패하거나 비어 있으면 섹션을 숨긴다(기존 스펙 5장 원칙).

### 3.2 F2~F5 전환 연출
| 단계 | body 클래스 | 화면 |
|---|---|---|
| F1 | `stage-input` | 위 3.1 |
| F2 | `stage-paper` | 제출 즉시. 하늘이 줄고(데스크탑 496→352px) 땅이 종이색으로 바뀜. 빈 결론 박스 + 깜빡이는 커서 + 입력한 꿈 인용문. **BE 응답을 기다리는 동안 이 화면이 로딩 표시를 겸한다.** |
| F3 | `stage-writing` | 응답 도착. 하늘이 한 번 더 줄고(→256px) 결론(`theme`)이 한 글자씩 타이핑됨 |
| F4~F5 | `stage-done` | 한 줄 코멘트 → 감정 키워드 → 설명 문단 → 도장 → 버튼 순으로 페이드인 |

- 순수 CSS transition + JS 타이머로 구현(라이브러리 없음). `prefers-reduced-motion`이면 타이핑·전환을 생략한다.
- 400/429/5xx/타임아웃이면 F1으로 되돌리고 기존과 같은 에러 처리(인라인 메시지 / 소진 팝업)를 한다.
- "다시 풀어보기"(모바일 "다시 풀기")는 F1으로 되돌리고 입력을 비운다.
- "앱에서 이어 쓰기"는 기존 소진 팝업의 앱 링크와 같은 곳(현재 `#`, 스토어 링크 미정)을 가리킨다.

## 4. 길흉 도장(Seal)

Figma 컴포넌트 `Seal · 길흉 도장`(672:15) 설명을 따른다: 吉 `#BE241F`, 凶 `#1E2836`(먹빛), 吉凶 `#49525F`(조건에 따라 갈림), 이중 원, 회전 -9°(Figma 기준 반시계 = CSS `rotate(9deg)`).

- 매핑: `CATEGORY_DICTIONARY[category].luck` `g`→吉, `h`→凶, `b`→吉凶(두 글자 세로). 사전에 없는 카테고리는 `b`.
- `LUCK_LABEL.b`를 "양면" → "조건에 따라 갈림"으로 바꾼다(Figma 범례 문구).
- 홈 F5의 큰 도장(92px)은 吉일 때 테마별로 약간 다른 붉은색을 쓴다(맑음 `#be241f` / 흐림 `#a03f3a` / 비 `#a43b36` / 눈 `#a83634`). 凶·吉凶은 컴포넌트 색 그대로.
- Figma 흐림 결과 샘플에 있는 "平" 도장은 우리 데이터 모델(g/h/b)에 없어 쓰지 않는다.
- 도장 DOM은 `categoryDictionary.js`의 `createSeal(luck)`가 만든다(홈·랭킹 공용).

### 4.1 폰트 — 凶 글리프 깨짐 대비
Figma 메모: Gowun Batang에 凶 글리프가 없으면 다른 폰트로 그려져 吉과 획 느낌이 달라질 수 있다. 세리프 스택을 `"Gowun Batang", "Noto Serif KR", serif`로 두고, Noto Serif KR은 Google Fonts `text=吉凶` 서브셋으로만 받는다(두 글자분 용량).

## 5. 랭킹 전체보기(`ranking.html`)

기존 `ranking.js`가 이미 Figma 의도와 상당 부분 맞는다(행별 독립 토글, 서버 데이터 그대로 렌더링, 모바일 요약 숨김, `scrollIntoView`). 바뀌는 것만 적는다.

1. **비주얼** — 한지색 배경 `#fbf8f0`, 가는 구분선 `#ebe4d3`, 네비게이션 바(데스크탑 "굿모닝 드림 … ← 홈으로" / 모바일 "← 전체보기").
2. **도장 배지** — 텍스트 배지를 4장 도장으로 교체.
3. **범례** — "吉 길몽 / 凶 흉몽 / 吉凶 조건에 따라 갈림", 목록 바로 위.
4. **F3 해몽 전 카드** — **오늘 목록에 내 꿈이 없으면**(기록 없음, 자정이 지나 어제 기록만 남은 경우 포함) 점선 테두리 카드 "아직 해몽한 꿈이 없어요 / 꿈을 풀어보면 오늘 몇 위인지 알려드려요 / [해몽하러 가기]"를 보여준다. 기존 id(`mine-card`/`mine-name`/`mine-rank`/`mine-goto`)를 그대로 쓰고 `is-empty` 클래스와 내용만 바꾼다. 버튼은 `index.html`로 이동하며, 홈이 로드 시 방문자 날씨로 테마를 정하므로 Figma 메모의 "맑음 고정" 문제는 생기지 않는다. 랭킹 로딩 자체가 실패하면 카드는 숨긴다.
5. **F4 순위 보기** — 클릭 시 내 꿈 행을 **펼치고** 스크롤한다(지금은 스크롤만).
6. **펼침 애니메이션** — `hidden` 즉시 토글 대신 `max-height` 트랜지션. 열린 뒤에는 `none`으로 풀어 창 크기가 바뀌어도 본문이 잘리지 않게 한다.
7. **모바일(640px 이하)** — 행에서 한 줄 요약을 숨기고 펼친 패널 안에 굵게 보여준다(Figma M F2). "내 꿈" 태그는 이름 옆으로 이동. 기존 480px 요약 숨김 규칙을 이 규칙으로 대체한다.
8. 날짜 줄 문구: "9월 9일 · 오늘 해몽된 꿈만 모았어요"(서버 `date`를 한국어 월·일로 변환).
9. 펼친 패널 하단의 "오늘 이 꿈을 해몽했습니다." 문구는 Figma에 없어 제거한다.

## 6. 반응형과 정렬

### 6.1 유동 스케일
고정 크기로 두 시안을 오가지 않는다. `style.css`에 `--f: calc((100vw - 360px) / 920)`(360px 화면 0px → 1280px 화면 1px)을 두고, 모든 크기를 `clamp(모바일값, calc(모바일값 + 차이 * var(--f)), 데스크탑값)`으로 쓴다. 두 시안 사이 모든 폭에서 값이 선형으로 보간된다.

컴포넌트 구조가 달라지는 곳만 640px 한 지점에서 분기한다: 입력 버튼(텍스트↔아이콘), 미리보기 카드 수(6↔3), 결과 날짜·버튼 문구 길이, 랭킹 네비게이션·행 구성.

### 6.2 정렬 보정 (Figma 좌표를 그대로 옮기지 않은 곳)
| Figma | 보정 |
|---|---|
| 데스크탑 날씨 표기가 오른쪽 110px 안쪽에 떠 있음(로고·"전체보기"는 46px) | 좌우 여백을 같은 거터로 통일 |
| 모바일 상단바 여백 20px, 미리보기 여백 24px | 같은 거터로 통일 |
| 모바일 입력 버튼이 위아래 6px, 오른쪽 18px 안쪽 | 사방 동일 간격으로 중앙 정렬 |
| 데스크탑 결과 영역이 왼쪽 200px·오른쪽 110px로 치우침 | 최대 폭 970px 중앙 정렬 |
| 결과 인용문이 결론 박스 하단 테두리와 겹침 | 박스 아래 16px 띄움 |
| 빗줄기 하나가 좌상단 모서리(0,0)에 떨어져 있음(패턴상 오른쪽 끝이어야 할 것이 좌표 순환으로 넘어감) | 오른쪽 끝으로 이동 |
| 빗줄기·눈송이가 날씨 표기 글자를 가로지름 | 장식 영역을 상단바 아래(64px)부터 시작 |
| 결과 화면 요소 간 간격이 데스크탑·모바일에서 불규칙 | 16/20px 리듬으로 통일 |
| 랭킹 페이지에서 검색바를 빼며 생긴 헤더–범례 빈 공간 | 범례 위 여백 제거 |

## 7. 파일 구성

| 파일 | 역할 |
|---|---|
| `WEB/style.css` | 공용: 리셋, `[hidden]` 규칙, 폰트 변수, `--f`, 길흉 도장 |
| `WEB/home.css` (신규) | 홈 전용: 테마 토큰, 하늘·땅·일러스트, 입력, 미리보기, 결과 연출, 팝업 |
| `WEB/ranking.css` (신규) | 랭킹 전용 |
| `WEB/categoryDictionary.js` | 사전 데이터 + `luckOf`, `createSeal` |
| `WEB/app.js` | 날씨·테마 적용, 랭킹 미리보기, 해몽 제출·단계 연출 |
| `WEB/ranking.js` | 랭킹 렌더링, 펼침, 내 꿈 카드 |

페이지별 CSS를 나눈 이유: 두 페이지가 공유하는 규칙이 도장·리셋뿐이고, 홈 연출 CSS가 커져 한 파일에 두면 서로의 선택자 충돌을 추적하기 어렵다. `[hidden]` 규칙은 계속 `style.css`에 둔다.

## 8. 유지해야 할 기존 계약

- 기존 id 전부 유지, 각 1개씩(`index.html` 15개, `ranking.html` 9개 — 구현 계획 검증 스크립트 참고). 새 id는 겹치지 않게 추가.
- `[hidden] { display: none !important; }` 규칙 유지.
- 서버에서 온 카테고리 이름은 `innerHTML`이 아니라 `textContent`로 넣는다(랭킹 목록·홈 미리보기 모두).
- 빌드 도구·프레임워크 없음.

## 9. 검증

빌드 도구가 없으므로 실제 실행으로 확인한다(`python -m http.server 5500 --directory WEB`).

| 확인 항목 | 합격 조건 |
|---|---|
| 문법 | `node --check`로 JS 3개 통과, CSS 괄호 짝 일치 |
| id 계약 | 검증 스크립트가 `OK` 출력 |
| 테마 4종 + 안개 | 콘솔 `applyTheme("clear"/"cloudy"/"fog"/"rain"/"snow")`로 각각 Figma 스크린샷과 색·문구·일러스트 일치 |
| F1→F5 | 로컬 BE로 실제 제출 시 단계가 끊김 없이 이어지고 최종 화면에 모든 필드 표시 |
| 에러 복귀 | BE를 끈 상태에서 제출 시 F1으로 돌아오고 "잠시 후 다시 시도해 주세요." |
| 도장 | 吉/凶/吉凶 색·글자·회전이 Figma와 일치, 凶이 다른 획 두께로 튀지 않음 |
| 랭킹 F3/F4 | `lastDreamCategory` 없을 때 해몽 전 카드, 있을 때 "순위 보기"로 펼침+스크롤 |
| 펼침 | 행마다 독립, 높이가 트랜지션으로 변함, 열린 상태로 창 폭을 줄여도 본문이 안 잘림 |
| 반응형 | 360 / 480 / 640 / 641 / 900 / 1280 / 1600px에서 가로 스크롤·겹침 없음 |
