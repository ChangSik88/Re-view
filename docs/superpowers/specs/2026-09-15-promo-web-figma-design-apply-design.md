## 1. 목적과 범위

기능은 이미 완성돼 있다(스펙·계획 문서 참고, Task 1~8 완료). 이 설계는 **그 위에 Figma WF 디자인을 입히는 작업**만 다룬다. 새 API·새 데이터 모델은 없다.

Figma WF 프레임에는 섹션 2개가 있다:
- `05 · 홈→해몽결과 플로우` — 날씨 5종 × 데스크탑/모바일 × 5단계(F1~F5)
- `06 · 꿈 랭킹 전체보기(한지)` — 데스크탑/모바일 × 4단계(F1 기본/F2 항목 펼침/F3 해몽 전/F4 순위 보기)

둘 다 이번 범위에 **포함**한다(랭킹 페이지는 최초 논의에서 제외했다가, Figma에 전용 디자인이 추가되면서 다시 포함으로 변경).

### 범위 밖
- 밤(夜) 테마 — Figma에 `D·밤`/`M·밤` 프레임이 있지만, 날씨 API 기반 테마링과 별개 축(시간대)이라 이번엔 적용하지 않는다.
- 랭킹 페이지 검색바 — Figma엔 있으나, 기존 프로젝트 결정(카테고리 13종 수준에선 장식에 가까움, `docs/superpowers/plans/2026-09-09-promo-web-page.md` Global Constraints)을 유지해 **완전히 제외**한다.
- 새 BE 엔드포인트, 새 DB 컬럼 — 없음.

## 3. 홈 화면(`index.html`) — F1~F5 전환 연출

전체 애니메이션을 구현한다(정적 전환으로 단순화하지 않음).

1. **F1 입력**: 히어로 블롭(태양/구름) + 날씨별 헤드라인 카피 + 입력바(데스크탑: 텍스트 버튼 "해몽 받기" / 모바일: 원형 화살표 아이콘 버튼) + 하단 "오늘 아침 많이 찾는 꿈" 미리보기(데스크탑 6칸, 모바일 3칸 — `flex-wrap` + 카드 `min-width`로 자동 개수 조절, 고정 브레이크포인트로 3/6 하드코딩하지 않음)
2. **F2 제출 직후**: 히어로 블롭이 축소되며 상단으로 이동, 결과 카드가 빈 채로 나타나고 커서 깜빡임, 사용자가 입력한 문장이 인용구로 표시
3. **F3 타이핑**: 결론 한 줄이 타이핑 효과로 채워짐
4. **F4~F5**: 한 줄 코멘트 → 설명 문단 → 吉/凶/吉凶 뱃지 → CTA(`다시 풀어보기` / `앱에서 이어 쓰기`) 순차 등장

구현은 순수 CSS transition + JS 타이머 체인(라이브러리 불필요). 기존 id(`weather-widget`, `dream-input`, `submit-btn`, `result`, `result-theme`, `result-vibe`, `result-feelings`, `result-reply` 등)는 그대로 쓰고, 이 요소들이 **보여지는 타이밍**만 단계적으로 바뀐다.

### 3.1 길흉 뱃지(신규, F5)
- `result.dream_category`를 `CATEGORY_DICTIONARY`(`categoryDictionary.js`)의 `luck` 값(g/h/b)과 매칭해 吉/凶/吉凶 도장을 F5에 표시.
- `categoryDictionary.js`를 `index.html`에도 `<script>`로 로드(현재 `ranking.html` 전용 → 공용 승격). BE 응답 스키마 변경 없음.

## 4. 랭킹 전체보기(`ranking.html`) — 변경 사항

기존 `ranking.js`/`style.css`가 이미 Figma 의도와 상당 부분 일치한다(행별 독립 토글, 서버 데이터 그대로 렌더링, 모바일에서 요약 숨김, `scrollIntoView` 등). Figma의 "구현 불가" 메모 12개 중 실제 조치가 필요한 것만 아래에 반영한다. 나머지는 Figma 프로토타입 자체의 한계일 뿐 지금 구현엔 해당 없음(부록 참고).

1. **吉/凶/吉凶 도장 배지** — 지금 텍스트 배지(`.badge-g/h/b`)를 원형 도장 스타일로 교체. 데이터 소스(`CATEGORY_DICTIONARY.luck`)는 그대로, CSS만 변경.
2. **범례(Legend) 바 신규 추가** — "길몽 / 흉몽 / 조건에 따라 갈림" + 도장 아이콘, 검색바 자리(제외됨) 대신 리스트 바로 위에 배치.
3. **F3 "해몽 전" 상태 추가** — `mine-card`가 기록 없을 때 완전히 숨는 대신, **같은 id(`mine-card`/`mine-name`/`mine-rank`/`mine-goto`) 안에서 내용만 분기**한다:
   - 기록 있음(기존): "내가 해몽한 꿈 / {카테고리} / 오늘 N위 / [순위 보기]"
   - 기록 없음(신규): "아직 해몽한 꿈이 없어요 / [해몽하러 가기]" — `mine-goto`가 스크롤 핸들러 대신 `index.html` 링크로 동작
   - id 개수·이름 계약 유지, 내용만 조건부.
4. **F4 "순위 보기" 동작 보강** — 지금은 `scrollIntoView`만 함. 클릭 시 해당 행에 `open` 클래스를 같이 부여해 스크롤+자동 펼침으로 보강.
5. **펼침 애니메이션** — `hidden` 즉시 토글 대신 `max-height` transition 적용.
6. **비주얼 톤** — 한지(크림 페이퍼) 배경 + 가는 구분선 + 세리프 헤드라인. 홈 화면(맑음 테마) 톤과 통일.

### 4.1 폰트 — 凶 글리프 깨짐 대비
Figma 메모: Gowun Batang에 凶 글리프가 없으면 대체 폰트로 그려져 吉과 획 느낌이 달라질 수 있음. 세리프 스택에 `Noto Serif KR`을 폴백으로 명시해 한자 렌더링을 통일한다(`font-family: "Gowun Batang", "Noto Serif KR", serif;`).

## 5. 반응형 전략

고정 브레이크포인트 전환이 아니라 유동적으로 스케일한다.
- 데스크탑(1280 기준)·모바일(360 기준) 시안을 양 끝으로 두고 `clamp()`/상대 단위로 그 사이를 보간.
- 컴포넌트 단위 변형은 필요한 곳만 분기: 입력 버튼(텍스트 ↔ 아이콘), 랭킹 미리보기 카드 개수(`flex-wrap`에 맡김).
- 장식 요소(빗방울/눈 점, 블롭)는 절대좌표 대신 컨테이너 기준 `%`/`em`으로 배치.
- 정렬이 깨져 보이는 장식 요소는 Figma 좌표를 그대로 복제하지 않고 flexbox/grid로 재정렬한다(빗방울·눈 점처럼 의도된 산개 배치는 유지하되, 우발적 미정렬은 정리).

## 6. 파일 변경 범위

- 수정: `WEB/index.html`, `WEB/ranking.html`, `WEB/style.css`, `WEB/app.js`, `WEB/ranking.js`
- 신규 파일 없음. Google Fonts CDN 링크(Gowun Batang, Noto Serif KR) 추가.
- `WEB/categoryDictionary.js`: 데이터 변경 없음, `index.html`에서도 로드.

## 7. 유지해야 할 기존 계약

- 기존 id 전부 유지 — 목록은 `docs/superpowers/plans/2026-09-09-promo-web-page.md` Task 7·8과 동일.
- `[hidden] { display: none !important; }` 규칙 유지(과거 이 규칙 누락으로 모달이 안 닫히는 버그가 있었음).
- 카테고리 이름은 `innerHTML`이 아니라 `textContent`로 채우는 원칙 유지(XSS 방지, 기존 주석 참고).
- `ranking.js`의 행별 독립 토글·서버 데이터 그대로 렌더링 로직은 그대로 — Figma 메모가 우려한 "고정 예시 12개" 문제는 애초에 해당 없음.

## 부록 — Figma "구현 불가" 메모 12개 판정

Figma 프로토타입(정적 화면 전환)의 한계일 뿐, 실제 웹 구현(서버 데이터 기반 JS)에는 대부분 해당하지 않는다.

| Figma 메모 | 판정 |
|---|---|
| 순위 규칙(동률 처리 등)을 고정 예시 12개로만 표현 | 해당 없음 — 실구현은 서버 응답 그대로 렌더링 |
| 검색 텍스트 입력/필터링 불가 | 실제 이슈였으나 검색바 자체를 제외하기로 확정(2절) |
| 카테고리 수 따라 목록 길이 가변 불가 | 해당 없음 — 이미 동적 렌더링 |
| 여러 행 동시 펼침 조합 표현 불가 | 해당 없음 — 이미 행별 독립 토글 |
| 펼침 높이 애니메이션이 Smart Animate 근사치 | 실제 이슈 — `max-height` transition으로 구현(4.5) |
| "해몽한 적 있는지" 조건분기를 별도 프레임으로 표현 | 해당 없음 — 이미 `sessionStorage` 기반 |
| "해몽하러 가기"가 맑음 홈 고정 | 해당 없음 — 실구현은 `index.html` 링크만 걸면 방문자 날씨 자동 반영(오히려 더 나음) |
| 내 꿈이 화면 밖(예 37위)일 때 스크롤 이동 표현 불가 | 해당 없음 — 이미 `scrollIntoView` 처리 |
| 집계 반영 전 "순위 보기" 버튼 상태 미정 | F3 상태 추가로 자연 해결(기록 없으면 버튼 자체가 "해몽하러 가기"로 대체) |
| 凶 글리프가 대체 폰트로 깨질 수 있음 | 실제 이슈 — `Noto Serif KR` 폴백 지정(4.1) |
| 모바일 한 줄 요약 숨김 | 해당 없음 — 이미 480px 미디어쿼리로 처리 |
| 모바일 스크롤 관성/바운스, 펼친 본문 길 때 보정 스크롤 | 브라우저 네이티브 동작에 맡김, 별도 구현 안 함 |
